# Title
SF-030 — Implement Bookmarks database schema and RLS

# Problem statement
Learners need a database schema to securely persist specific video timestamps (bookmarks) to return to important concepts later.

# Scope
Create the PostgreSQL database table, constraints, and Row Level Security (RLS) policies for user bookmarks.

# Technical requirements
- Create migration script for `bookmarks` table.
- Table columns: `id` (UUID), `user_id` (UUID), `learning_item_id` (UUID), `youtube_video_id` (Text), `position_seconds` (Integer), `label` (Text), `created_at` (Timestamptz).
- Foreign keys: `user_id` -> `auth.users(id)`, `learning_item_id` -> `learning_items(id)`.

# Database/API/UI boundaries where applicable
- Strictly isolated to the Supabase Database layer (Migrations and RLS).

# Acceptance criteria
- Migration runs successfully against a clean local database.
- Database enforces `position_seconds >= 0`.

# Testing requirements
- Add database RLS tests (`tests/integration/db-rls.test.ts`) to ensure cross-user isolation for bookmarks.

# Security/RLS requirements
- Enable RLS on `bookmarks`.
- `auth.uid() = user_id` must be enforced for SELECT, INSERT, UPDATE, DELETE.

# Explicit out-of-scope items
- Bookmarks API routes.
- Frontend UI and IFrame integration.
- Analytics or tagging.

# Dependencies
- SF-029 — Build Notes UI in learning view

# Definition of Done
- Migration is reproducible.
- RLS tests pass denying unauthorized and cross-user access.
- PR is reviewed and merged.
