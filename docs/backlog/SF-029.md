# Title
SF-029 — Build Notes UI in learning view

# Problem statement
Users need a clean, distraction-free interface inside the `/learn/[id]` playback view to actively take and review notes.

# Scope
Create the frontend React components to interact with the Notes API and display them in the learning view.

# Technical requirements
- Build a `NoteEditor` component (textarea or lightweight markdown editor).
- Build a `NoteList` component to render saved notes.
- Integrate fetching and saving via `useSWR` or standard `useEffect`/fetch patterns.
- Ensure component styling matches Figma design tokens (globals.css).

# Database/API/UI boundaries where applicable
- Strictly Frontend UI layer interacting with the previously built `/api/notes`.

# Acceptance criteria
- User can type and save a note without video playback reloading.
- Saved notes appear immediately in the note list.
- User can edit or delete an existing note.
- UI gracefully handles loading and error states (e.g. "Failed to save note").

# Testing requirements
- E2E Playwright test simulating writing and saving a note during playback.

# Security/RLS requirements
- HTML input must be safely rendered to prevent XSS (if using markdown/rich text).

# Explicit out-of-scope items
- Backend API creation (handled in SF-028).
- Tagging, categorization, rich-media attachments, or AI summarization.

# Dependencies
- SF-028 — Implement Notes API and Service layer

# Definition of Done
- Component handles all states (Empty, Loading, Error, Success).
- Keyboard accessibility maintained (tab navigation through form).
- E2E test passes.
- PR is reviewed and merged.
