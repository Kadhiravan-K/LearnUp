# Title
SF-028 — Implement Notes API and Service layer

# Problem statement
The client application needs a secure backend mechanism to fetch, create, update, and delete user notes.

# Scope
Create the server-side API routes and repository methods for Notes CRUD operations.

# Technical requirements
- Implement `NotesRepository` for database abstraction.
- Create Next.js App Router API endpoints under `/api/notes`.
- Support `GET`, `POST`, `PUT`, and `DELETE` HTTP methods.
- Define request and response TypeScript interfaces.

# Database/API/UI boundaries where applicable
- Isolated to the Next.js API Routes and Server Services. No UI components.

# Acceptance criteria
- All endpoints correctly route through the established authentication token verifier.
- Endpoints return standard stable error codes (e.g., 401, 404, 400).
- Input validation sanitizes the `content` body payload.

# Testing requirements
- Add unit tests for `NotesRepository`.
- Add integration tests for `/api/notes` endpoints in `tests/integration/api-qa.test.ts`.

# Security/RLS requirements
- API endpoints must enforce user authentication.
- API operations must rely on the scoped Supabase client to trigger underlying DB RLS.

# Explicit out-of-scope items
- Frontend Notes UI.
- Tagging, categorization, sharing notes.

# Dependencies
- SF-027 — Implement Notes database schema and RLS

# Definition of Done
- API endpoints implemented and documented.
- Automated API integration tests pass.
- PR is reviewed and merged.
