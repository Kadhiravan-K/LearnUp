# Title
SF-031 — Implement Bookmarks API and Service layer

# Problem statement
The client application needs a secure backend API to fetch, create, and delete bookmarks at specific video timestamps.

# Scope
Create the server-side API routes and repository methods for Bookmarks CRUD operations.

# Technical requirements
- Implement `BookmarksRepository` for database abstraction.
- Create Next.js App Router API endpoints under `/api/bookmarks`.
- Support `GET`, `POST`, and `DELETE` HTTP methods (updating timestamp position is out of scope).
- Define request and response TypeScript interfaces.

# Database/API/UI boundaries where applicable
- Isolated to the Next.js API Routes and Server Services. No UI components.

# Acceptance criteria
- Endpoints return standard stable error codes (e.g., 401, 404, 400).
- Input validation ensures `position_seconds` is provided and valid (>= 0).
- Cross-user validation handled seamlessly by RLS scoping.

# Testing requirements
- Add unit tests for `BookmarksRepository`.
- Add integration tests for `/api/bookmarks` endpoints in `tests/integration/api-qa.test.ts`.

# Security/RLS requirements
- API endpoints must enforce user authentication.
- API operations must rely on the scoped Supabase client to trigger underlying DB RLS.

# Explicit out-of-scope items
- Frontend Bookmarks UI.
- Tagging or categorizing bookmarks.

# Dependencies
- SF-030 — Implement Bookmarks database schema and RLS

# Definition of Done
- API endpoints implemented and documented.
- Automated API integration tests pass.
- PR is reviewed and merged.
