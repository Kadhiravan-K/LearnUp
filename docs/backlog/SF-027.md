# Title
SF-027 — Implement Notes database schema and RLS

# Problem statement
Learners need a persistent storage mechanism to save contextual notes related to their imported learning items. 

# Scope
Create the PostgreSQL database table, constraints, and Row Level Security (RLS) policies for user notes.

# Technical requirements
- Create migration script for `notes` table.
- Table columns: `id` (UUID), `user_id` (UUID), `learning_item_id` (UUID), `youtube_video_id` (Text), `content` (Text), `created_at` (Timestamptz), `updated_at` (Timestamptz).
- Foreign keys: `user_id` -> `auth.users(id)`, `learning_item_id` -> `learning_items(id)`.

# Database/API/UI boundaries where applicable
- Strictly isolated to the Supabase Database layer (Migrations and RLS). No API or UI changes.

# Acceptance criteria
- Migration runs successfully against a clean local database.
- `notes` table enforces foreign key relationships safely (cascade deletions if learning item is removed).

# Testing requirements
- Add database RLS tests (`tests/integration/db-rls.test.ts`) to ensure cross-user isolation.

# Security/RLS requirements
- Enable RLS on `notes`.
- `auth.uid() = user_id` must be enforced for SELECT, INSERT, UPDATE, DELETE.

# Explicit out-of-scope items
- Notes API routes.
- Frontend Notes UI.
- Tagging, categorization, sharing notes, or AI summaries.

# Dependencies
- None

# Definition of Done
- Migration is reproducible.
- RLS tests pass denying unauthorized and cross-user access.
- PR is reviewed and merged.
